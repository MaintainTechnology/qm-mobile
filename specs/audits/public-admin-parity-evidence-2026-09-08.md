## Cross-cutting corrections and required acceptance

1. Both platforms deliberately scope claimed HTTPS app links to `/app` and `/app/*`. `W/lib/mobile-app-associations.ts:16` sets the iOS path restriction; domain names in iOS entitlements do not alone claim every path. The supplied backlog's iOS-whole-domain mismatch claim is obsolete/incorrect. Actual hosted association responses, Apple team identity, signing fingerprints, cold/warm start and provider returns remain unverified. Attempts to retrieve public production association/policy URLs with the browsing tool returned safe-open errors, not an HTTP status; this is not proof the deployed endpoints fail.
2. `M/src/lib/destinations.ts:103` intentionally rejects customer HTTPS routes outside `/app`. Keep those browser routes working until native counterparts and their audience/token controls exist. Do not widen associations ahead of supported routing.
3. The old ledger contains 365 valid rows, including 327 labelled `Not started` and zero fully verified rows. Many labels predate implemented code. Those are tracker statuses, not 327 absent features or a measured completion percentage.
4. For every completed native journey, prove read → action → server persistence → refetch → close/reopen/relaunch. Include wrong tenant/role, expired/replayed token, signed-out continuation, network loss after write, cancellation, empty/missing record and return/back behaviour. Provider success screens are not evidence of payment, delivery or account entitlement.
5. Existing Playwright tests run Expo **web** with backend mocks and a live Clerk development setup (`M/playwright.config.ts:1`, `M/e2e/global-setup.ts:1`). They are not iPhone/TestFlight tests. The setup creates/changes a Clerk QA account, so it was not run during this read-only audit. A complete real-provider journey and App Store certification require separate authorized staging/device evidence.
