# QuoteMax mobile versus web: core business-workspace evidence

Date: 8 September 2026. Read-only application-source comparison, with an audit document as the only output. This report covers the CORE business workspace; authentication, store billing, public/customer and administrator journeys, and detailed trade tools are covered by the companion audit.

## Verdict and evidence boundaries

**The mobile app does not yet have full web feature parity.** It already contains substantial native functionality, so the old requirement ledger must not be interpreted as a count of unbuilt screens. Major daily-work gaps remain in the unified quote queue, post-site-visit payment sequence, document editing, business-account editing and quote policies. Several smaller screens have functioning native implementations with incomplete controls. CRM and flyer/Canva workflows are browser handoffs; Brand Studio has no native destination.

“Native present” below means an actual screen, data request or mutation was found in current source. It is not a statement that a real account, payment, SMS, file upload or physical device was exercised. This sub-audit did not launch a live application, send messages, invoke paid providers, change backend data, or run device tests. The parent audit supplies the local verification results. Full parity is a product target; Apple does not require every web feature to be copied into an app before accepting it.

## 6. Corrections to the attached backlog and old ledger

1. **No numerical completion percentage is defensible from the old ledger.** Native implementations are broader than many “Not started” rows, but no source count proves real end-to-end acceptance.
2. **Do not root-filter follow-ups.** Unpaid final quotes belong in the chase queue; balance invoices do not. The API already enforces this.
3. **Chain actions belong to different rows.** Issue final is on the paid initial inspection; request balance is on paid final deposit/credit, not on that same initial row.
4. **Business address already exists in DB/onboarding.** The missing part is existing-user management through `/tenant/me` and account UI.
5. **Analytics are already native and server analytics already filters roots.** Home's locally calculated KPI totals still need the chain correction, plus selectable periods and prefiltered attention navigation.
6. **Selected-tier line items already render.** Remaining gaps are all-tier inspection/selection, line totals and native report/editor workflow.
7. **Calendar tenant timezone is already implemented.** Old CORE-095 wording describing device-local formatting is stale. Physical-device/DST verification remains separate.
8. **Video default labelling already exists.** Personalisation, generate-both and explicit own-video wording remain.
9. **Payout completion handling is materially improved.** Completion, release, blocked and in-flight results are distinct, balance null is not zero, and provider return triggers refetch. Broader payout overview remains incomplete.
10. **Per-trade quote presentation modes already save natively.** Tenant-wide review/follow-up/default-layout/early-bird controls are separate gaps.
11. **History calibration is native; invoice calibration is not.** They use separate contracts and must not be conflated.
12. **First-party browser links are parity handoffs, not implementation.** Provider-owned Canva/Stripe interfaces can appropriately remain external with a complete native lifecycle wrapper.

## 7. Recommended sequencing within this CORE scope

1. **Correct data/money behaviour first:** quote-chain counts/conversion/badges/actions and child-send semantics; repair B06 tier and quiet-save authority. Preserve paid guards and explicit human send.
2. **Finish the daily work loop:** one consistent searchable quote/job queue → native detail/report/PDF → edit/review/save/send → schedule → complete/release. Add correct failure and return recovery at each step.
3. **Complete business setup:** account/availability/licences/trade management; global quote policies; invoice calibration after upload hardening.
4. **Finish existing smaller screens:** chat/follow-up filters/history, calendar summaries, payout overview, Files viewer/comments, History import/review and QR management.
5. **Complete optional full-parity marketing tools:** CRM/Canva lifecycle, flyer designer, hardened Brand Studio and video personalisation. A deliberate limited release can omit these, provided product scope, navigation and store claims honestly match shipped behaviour.
