## Scoring rubric — fixed before implementation

Score the complete requested scope, not just the latest slice. An independent review PASS still requires every specification acceptance item; a numerical score never overrides that rule.

| Dimension | Points | Calculation |
|---|---:|---|
| Specification delivery | 60 | Average evidence fraction across the 95 non-decision work packages ×60. Each package earns 0 when unverified/missing, 0.25 for reviewed partial implementation, 0.50 for complete implementation awaiting meaningful tests, 0.75 for independent review plus passing relevant local behavioural tests, and 1.00 only with all package acceptance evidence including persistence/device/provider proof or reviewed non-applicability. Existing functionality must be verified to earn credit. |
| Critical invariants | 20 | Ten checks worth 2 each: server identity/tenant isolation; role/trade/entitlement isolation; owned pricing/GST; stale input/rate rejection; save-versus-send; idempotent unknown-outcome recovery; durable save/refetch/reopen; account-switch/privacy isolation; bounded untrusted input; provider-return reconciliation. Each earns 0 unverified/failing, 1 for passing focused local proof in changed paths, 2 for all required paths and environment proof. |
| Reproducible verification | 10 | 2.5 each for current passing typecheck, canonical lint, complete mobile unit suite, and relevant paired backend contract suites. Record exact commands and failures. No points from skipped/live-dependent tests or historical logs. |
| Release evidence | 10 | One point each for fully passed R01–R10 under the actual release manifest; no points for source-only configuration or an unsupported non-applicability assumption. |

Round only the final total to one decimal. Any unresolved enabled P0 correctness/security blocker caps the score at 59; absence of installed iOS/provider evidence caps it at 84. These are ceilings, not awarded points. Decisions DEC01–DEC04 are recorded separately and block their dependent acceptance.

The improvement loop is build → independent review → fix failed acceptance → rerun affected checks → rescore. A meaningful score increase is at least **2 points out of 100**. After full required work passes, stop optional revision when two consecutive targeted refinement passes improve by less than 2 points. Plateau cannot justify abandoning an unimplemented requirement or claiming a blocked release passed. Preserve passing behaviour while fixing the weakest evidence/implementation areas.
